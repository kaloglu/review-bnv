# AGENTS.md

This document helps AI agents contribute effectively to this Flutter codebase.

1) Project overview and purpose
- App: Raffle/Giveaway platform ("BedavaNevar") where users sign in, browse raffles, spend tickets to enroll, view winners/history, and earn tickets via rewarded ads and invites.
- Platforms: Android, iOS, Web, desktop targets present.
- Backend: Firebase-first (Auth, Firestore, Messaging) with FirebaseUI for authentication flows.

Note: In Dreamflow, connect Firebase via the Firebase panel in the left sidebar before using any backend features. Do not set up backends via CLI here.

2) Architecture and conventions
- Layered structure (logical, not strict Clean Architecture):
  - Presentation (UI/widgets, Riverpod providers colocated for screens)
  - Domain (pure data models that map to Firestore docs)
  - Data (platform/infra services: auth gate, connectivity, messaging, keys)
- State management: Riverpod (ProviderScope in main.dart). Providers use StreamProvider/autoDispose for Firestore streams and timers.
- Navigation: MaterialApp with an AuthGate that decides between FirebaseUI sign-in flows, profile completion, and the HomeScreen. Some named routes are defined inside AuthGate.
- Backend:
  - Firebase Core initialized in main.dart using firebase_options.dart
  - Auth: firebase_auth + firebase_ui_auth (providers: Google, Facebook, Twitter, Phone)
  - Database: cloud_firestore
  - Messaging: firebase_messaging (background handler stub)
  - Ads: google_mobile_ads with RewardedInterstitial
  - Notifications: overlay_support
  - Deep links: flutter_branch_sdk placeholder

3) Important directories
- lib/Presentation/
  - screens/: All pages (home, profile, product details, ticket/enroll/winner history, edit profile)
  - providers/: Riverpod providers for features (fetching raffles, time remaining, enrollments, etc.)
  - constants/: Style tokens (colors, text styles), static data, enums, helpers (date formatting, shimmer)
  - utils/: Reusable UI parts and helpers (buttons, textfields, pickers, overlays, layout spacing, language strings)
- lib/Domain/models/: Firestore data models (e.g., ProductModel, ProductInfo, Rules, EnrollModel, TicketModel, ProfileModel)
- lib/Data/services/: Cross-cutting/platform services (AuthGate, Firebase Messaging, connectivity helper, OAuth keys)
- lib/firebase_options.dart: Firebase configuration (generated by Firebase setup)
- assets/: App images/icons used in UI
- android, ios, macos, linux, windows, web/: Platform directories
- test/: Tests scaffold

4) Code style guidelines and naming
- Dart/Flutter
  - Classes: PascalCase; methods/variables: lowerCamelCase
  - Files: Prefer snake_case for new files (no spaces). Keep folder capitalization consistent with existing structure (e.g., Presentation/)
  - Imports: Prefer package imports (e.g., package:cihan_app/...) for new code; avoid mixing with deep relative imports
  - Logging: Use debugPrint(...) for errors and diagnostics
  - Null safety: Prefer final fields and required constructors; only use late where strictly necessary
- UI
  - Centralize typography in Presentation/constants/text_styles.dart (GoogleFonts Poppins used). Extend or reuse rather than hardcode styles
  - Centralize colors in Presentation/constants/app_colors.dart; avoid hardcoded Color values in widgets
  - Favor small, reusable widgets placed in Presentation/utils/
- Providers
  - Place Riverpod providers in Presentation/providers
  - Name providers descriptively, scope to feature (e.g., productsStreamProvider)
  - Use autoDispose for UI-scoped streams/timers to avoid leaks

5) Common implementation patterns
- Firestore-backed feature
  1) Model (Domain/models)
     ```dart
     class ExampleModel {
       final String id;
       final String title;
       const ExampleModel({required this.id, required this.title});
       factory ExampleModel.fromJson(Map<String, dynamic> json, String id) =>
         ExampleModel(id: id, title: json['title'] as String? ?? '');
       Map<String, dynamic> toJson() => {'title': title};
     }
     ```
  2) Provider (Presentation/providers)
     ```dart
     final examplesProvider = StreamProvider<List<ExampleModel>>((ref) {
       return FirebaseFirestore.instance
         .collection('examples')
         .snapshots()
         .map((s) => s.docs
           .map((d) => ExampleModel.fromJson(d.data(), d.id))
           .toList());
     });
     ```
  3) UI (Presentation/screens)
     ```dart
     class ExampleList extends ConsumerWidget {
       const ExampleList({super.key});
       @override
       Widget build(BuildContext context, WidgetRef ref) {
         final examples = ref.watch(examplesProvider);
         return examples.when(
           loading: () => const CircularProgressIndicator(),
           error: (e, st) { debugPrint('load err: $e'); return const Text('Error'); },
           data: (items) => ListView.builder(
             itemCount: items.length,
             itemBuilder: (_, i) => ListTile(title: Text(items[i].title)),
           ),
         );
       }
     }
     ```
- Auth-gated flows
  - Use FirebaseAuth.instance.authStateChanges() to branch unauthenticated vs authenticated
  - When authenticated, read user document to decide onboarding/profile completion vs home
- Connectivity
  - ConnectivityService (Data/services/connectivity.dart) exposes a broadcast stream and flags to display offline UI/state after a grace period
- Rewarded ads
  - Use createRewardedInterstitialAd() once; call showRewardedInterstitialAd() then handle onUserEarnedReward to write to Firestore; always set callbacks and recreate on dismissal/failure
- Strings and i18n
  - Use AppStrings (Presentation/utils/lang.dart) constants; currently Turkish strings are primary. Add new strings there for consistency

6) Project-specific rules and constraints
- Dreamflow backend setup
  - No backend is connected by default. Use the Firebase panel (left sidebar) to connect a Firebase project, enable Auth providers, and configure platforms. Avoid CLI/console-based setup in this environment
- Secrets handling
  - Do not hardcode new secrets in source. The existing Keys class contains example IDs; for new work, prefer Dreamflow-managed secrets or runtime-configured values
- Imports and case sensitivity
  - Some files use package:cihan_app/... while others use relative paths; and there are case inconsistencies between imports and folders. When adding new imports, match actual path casing and prefer package imports to avoid case-sensitivity issues on some platforms
- Naming hygiene
  - Avoid spaces/typos in new filenames (e.g., prefer ad_reward_profile_screen.dart). Keep provider filenames consistent (<feature>_provider.dart)
- Error handling & logging
  - Wrap async Firebase and plugin calls in try/catch; log with debugPrint and surface user-friendly messages via overlay_support or UI where appropriate
- Performance
  - Use autoDispose for UI-bound providers and avoid doing heavy work in build methods. Prefer mapping/transforming Firestore streams in providers rather than screens
- Design consistency
  - Use centralized text styles and colors; avoid hardcoding inline styles. Reuse UI utilities/components from Presentation/utils whenever possible

Appendix: Key entry points
- main.dart: Initializes Firebase, MobileAds, Messaging, configures FirebaseUI providers, wraps app in ProviderScope and OverlaySupport
- Data/services/auth_gate.dart: Sign-in screens (FirebaseUI), routing, and post-auth branching to profile completion or home
- Presentation/providers/*: Riverpod data sources for screens
- Presentation/screens/*: Page UIs

If anything is unclear or you encounter platform-specific errors, check the Dreamflow Debug Console and logs. Prefer minimal, focused changes that respect the existing layering and provider patterns.
